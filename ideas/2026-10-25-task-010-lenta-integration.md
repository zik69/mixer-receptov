# Task-010 — Интеграция с Лентой (цены и наличие)

Дата: 2026-10-25
Режим: B (проработанная идея из roadmap)

## Идея в одном предложении

Показывать для каждого ингредиента из списка покупок цену и наличие в выбранном магазине Ленты, чтобы пользователь сразу видел, во сколько обойдётся ужин и чего нет в наличии.

## Для кого и какая боль

Пользователь планирует меню и идёт в Ленту. Сейчас он видит только список продуктов с количествами, но не знает цен и наличия. Приходится открывать приложение Ленты отдельно и искать каждый товар.

## Допущения

- У Ленты есть публичный Integration API, который можно вызывать из браузера (CORS разрешён).
- Пользователь выбирает один магазин Ленты (по городу/адресу) один раз.
- Названия ингредиентов из словаря можно сопоставить с товарами Ленты по текстовому поиску (поле lentaQuery уже есть в ingredients.json).
- Приложение остаётся статическим сайтом без бэкенда.

## Варианты

| Вариант | Суть | Плюсы | Минусы | Цена и риск |
|---|---|---|---|---|
| A. Автопоиск цен | Для каждого ингредиента ищем товар в Ленте, берём цену | Удобно, всё автоматически | CORS, скорость, точность сопоставления | Высокая сложность, высокий риск |
| B. Ручной ввод цен | Пользователь сам вводит цену рядом с ингредиентом | Надёжно, без API, работает оффлайн | Много ручной работы | Низкая сложность, низкий риск |
| C. Только наличие (есть/нет) | Проверяем, есть ли товар, без цены | Проще чем A, полезнее чем B | Всё равно нужен API и сопоставление | Средняя сложность |
| D. Не делать | Пользователь открывает приложение Ленты отдельно | Ноль затрат | Менее удобно | Нет риска |

## Сильные стороны

- Реальная ценность: планирование бюджета на неделю.
- Задел уже есть: в ingredients.json у каждого ингредиента есть поле lentaQuery.
- Можно показать «чего нет в наличии» — помогает заранее заменить продукт (связь с Task-013).

## Возражения

1. **CORS-блокировка.** Браузер может заблокировать запросы к API Ленты, если сервер не отдаёт заголовки CORS. → Проблема: интеграция из браузера невозможна без прокси/бэкенда. Снимается, если API разрешает кросс-доменные запросы или есть серверная функция.

2. **Точность сопоставления.** «Лук репчатый» может соответствовать десятку товаров с разными ценами и весами. → Проблема: неверная цена или неверный товар. Снимается, если пользователь выбирает товар из списка или берёт самый дешёвый вариант с пометкой.

3. **Скорость и нагрузка.** 10–15 ингредиентов × запросы к API = медленно на мобильном интернете. → Проблема: долгая загрузка, разряд батареи. Снимается кэшированием и параллельными запросами с лимитом.

4. **Оффлайн.** В магазине без интернета цены не загрузятся. → Проблема: функция бесполезна в момент покупки. Снимается кэшем последних цен в localStorage.

5. **Хрупкость API.** Лента может изменить API, и интеграция сломается. → Проблема: приложение зависит от внешнего сервиса. Снимается изоляцией: при ошибке просто не показываем цены, не ломаем остальное.

6. **Приватность.** Запросы к API раскрывают список покупок (хоть и анонимно). → Проблема: минимальная, но есть. Снимается отсутствием аккаунта и персональных данных.

## Убийственное условие

API Ленты должен быть доступен из браузера (CORS) или нужен прокси/бэкенд. Если нет — задача невозможна в текущей архитектуре (статический сайт без сервера). Это нужно проверить в первую очередь.

## Рекомендация

Сначала сделать дешёвую проверку CORS. Если API доступен — делать упрощённую версию A (цена рядом с ингредиентом, автопоиск по lentaQuery, без выбора товара). Если CORS нет — перейти к варианту B (ручной ввод цен) или D (не делать).

## Первый шаг и дешёвая проверка

Открыть консоль браузера на сайте и выполнить fetch к API Ленты (например, поиск товара по «лук»). Посмотреть: приходит ли ответ или блокирует CORS. Это занимает 5 минут и не требует кода.

## Критерий успеха и провала

- Успех: цены и наличие показываются для 80%+ ингредиентов из списка покупок.
- Провал: CORS блокирует запросы, или сопоставление даёт неверные цены чаще чем в 30% случаев.
